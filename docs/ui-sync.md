# 会话与界面同步

## 检查发现

1. `thread/start` 和 `thread/name/set` 可以持久化一个没有消息的 Codex 会话。当前客户端原生列表会过滤空会话，按工程或精确 ID 请求列表也不能替代 `thread/read`。后台对象存在不等于侧栏可见，重启不能解决这个过滤条件。
2. 插件的空会话索引只被 `peer_sessions` 使用，Codex 不读取它。之前没有在创建回执中区分这两种列表，容易把后台成功误报为界面同步成功。
3. `codex queue` 可以为未加载的会话保存消息。保存队列不一定恢复会话；模型尚未处理时，聊天历史和预览仍为空，因而可能继续不在侧栏中。仅有入队 ID 不能证明 UI 中存在这条消息。

## 当前处理

- 创建保持空会话语义，不发送虚假消息、不自动开始模型、不跳转当前窗口。保留 `created: true` 与原 ID，单独返回 `backendCreated`、`completed: false` 和 `session.desktopSync`；探测失败也不能诱导重复创建。
- `peer_sessions` 给原生列表记录和由插件索引补全的记录分别标记 `listed` 与 `not-listed`。原生列表可见性与屏幕可见性分开，`liveUiVerified` 保持 `false`。
- 匹配本机桌面时返回 `openUrl`，用户可以打开已经创建的会话；不修改客户端文件、数据库、侧栏状态或二进制。
- 新消息先持久化入队，再调用客户端现有的 `codex://threads/wake/<id>` 入口请求后台恢复。该入口检查是否有待处理队列，不导航、不添加额外消息。这里只报告 `desktopActivation.state: requested`，不宣称模型收到或任务完成。
- 桌面不可用或入口启动失败时保留原入队回执与消息 ID，附带恢复提示。不要重发同一消息；必要时手动打开已有会话。该入口依赖客户端版本，未知或旧版客户端是否消费队列仍需实测。
- 历史积压消息不会在升级或安装时自动重放；已有业务队列需要用户明确决定是否继续，避免旧交接或变更任务被意外执行。

## 验收范围

需要分别记录：后台对象、原生列表、应用聊天目录、实际窗口、模型处理和归档状态。应用工具能列出会话只证明应用目录收录，不能代替屏幕观察。空会话被客户端隐藏仍是现有产品行为，插件不伪造聊天内容绕过。

源码回归覆盖空会话与原生列表的区别、探测失败保留创建 ID、先入队再唤起、唤起失败保留入队 ID、桌面禁用、远程/隔离配置不误唤起本机桌面、目标 UUID 校验和 Electron 宿主环境隔离。真实客户端验证使用专用测试会话，不改动已有交接队列；需要用户查看结果时保留该测试会话，之后可单独归档。

### 2026-11-27 本机验证

- 当前 Codex CLI 为 `0.171.0-alpha.13.2`。隔离配置下，空会话默认列表、数据库列表、按工程列表、按精确 ID 列表均不返回；进程重启后仍可按 ID 读取。
- 使用本分支的实际适配器，在已有工程内新建专用空会话，入队一条只要求固定回复的测试消息，再请求本机桌面唤起。实际模型回复了约定文本，队列清空，回合完成，原生列表收录。
- Codex 应用自己的聊天目录收录了同一个会话，归属正确的桌面工程；应用历史接口能读取测试消息与模型回复。没有进行屏幕视觉检查，不将目录证据标记为 `liveUiVerified: true`。
- 本地完整回归 71 项：70 项通过，1 项未运行（可选 DSH 网关独立生命周期测试）；真实 Codex 创建、改名、归档、恢复测试已运行。
- 这是分支源码验证，日常 DSH 中已安装的插件未被替换，客户端未被重装或重启。新行为需要使用包含修复的插件代码；公开的 `v0.5.2` 发布包不因本地改动而改变。
